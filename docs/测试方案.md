# 项目能力测试方案

> 2026-09-23 定稿。配套语料扩写计划（docs/语料评测记录.md）使用：
> 语料扩写解决「单轮判得准」，本方案补齐「多轮接得住、记忆不丢、端到端不塌」。

## 0. 能力面盘点（测什么）

| 能力层 | 代码位置 | 现有覆盖 | 缺口 |
|---|---|---|---|
| 顶层意图 + 子类型识别（13 域，embedding 中心向量，阈值 0.65） | `agent/intent/classifier.py` | `tools/eval_intent.py`（~80 例，normal/boundary/incident）、`tests/test_intent_classification.py` | **无负样本（应判 other 的域外话术）**、无对抗鲁棒集、无阈值灰区分析 |
| 槽位抽取 + 时间解析 | `agent/intent/slots.py` | `tests/test_slots.py` | 负样本（非法时间、空实体） |
| 会话上下文 / 多轮（追问、放弃、接管、子类型继承） | `app.py` 情况 1/1.5/2 分支、`memory/session_state.py`、各 handler | `tests/test_handlers.py`、`test_graphs.py` 零散覆盖 | **缺系统的多轮场景矩阵**：超时、跨会话隔离、接管、省略式追问无回归集 |
| 对话记忆（窗口 k=10 + 三种持久化） | `memory/store.py`、`memory_persistor_{json,sqlite,mysql}.py` | 无 | **完全空白**：窗口截断、重启恢复、三实现一致性、会话隔离 |
| 端到端（WebSocket 事件序列） | `app.py::agent_ws` / `asr_ws` / `doc_ws` | 无（test_graphs 是进程内 FakeTool） | 事件顺序断言（answer 后必须 done，排查记录案例 14）、故障注入 |
| LLM 回答质量（RAG 知识库 / 文档生成） | `graph/knowledge_qa_langgraph.py`、`gen_doc_pipeline.py` | 无 | LLM-as-judge 抽评 |
| 性能 | `tests/test_performance.py` | 分类/槽位/图/并发基准 | 多轮状态内存增长、记忆持久化耗时 |

关键边界（测试设计必须尊重）：
- **意图分类器是单轮的**：`classifier.py` 不读 chat_history。省略式追问（「昨天呢」）靠 `session_state` 的子类型继承（`_SUBTYPE_FALLBACKS`），不是靠记忆。→ 上下文测试和记忆测试要分开设计，各自验证各自机制。
- 追问态（`is_waiting`）下**不跑意图分类**，靠 `handler.handle_reply` 判断相关性 → 追问轮的分类行为和空闲轮完全不同，必须分别测。

## 1. 分层总览

| 层 | 名称 | 依赖 | 形态 |
|---|---|---|---|
| L1 | 意图识别评测 | embedding 模型（不启动 app、不打 LLM） | 离线批跑，`tools/eval_intent.py` |
| L2 | 槽位抽取 | jionlp | pytest |
| L3 | 会话上下文 / 多轮场景 | 无模型（handler + session_state 进程内） | pytest + 场景脚本 |
| L4 | 记忆 | 无 LLM（persistor 用临时文件/测试库） | pytest |
| L5 | 端到端 WS | 真实容器服务 + FakeTool 后端 | 冒烟脚本 + pytest |
| L6 | LLM 回答质量 | 真 LLM | 抽样评测脚本 + 人工复核 |
| L7 | 性能 | 模型 | pytest `-m performance`（已有） |

## 2. L1 意图识别评测（扩展 eval_intent.py）

### 2.1 用例集扩到 6 类标签

现有 `normal / boundary / incident` 之外新增三类，全部进 `tools/eval_intent.py` 的 `CASES`：

**① negative（域外负样本，期望 `other`）** — 当前完全缺失，这是误响应的唯一防线：

```
- 闲聊寒暄：你好 / 讲个笑话 / 你叫什么名字
- 域外业务：今天天气怎么样 / 帮我订机票 / 附近有什么餐厅推荐
- 开放问答：唐诗床前明月光的作者是谁 / 地球到月球多远
- 指令类：打开音乐 / 把空调调到26度（无设备控制域）
- 相邻域易混词：告警处理一下（无操作意图域）、给我发个通知（无消息发送域）
目标规模：≥100 条，覆盖 13 域的中心向量邻近区
```

**② adversarial（对抗鲁棒）** — 期望仍是原意图：

```
- 错别字/同音字：张三现在再哪 / 查下张三的轨际
- 标点/空格/全半角：今 天 园 区 多 少 人 /  停车场还有多少空位？
- 语气词后缀：现在有多少人呀 / 帮我看下能耗哈 / 用电排名呗
- 中英混杂：查一下 meeting room 有几间空 / iot设备总数
- 长度极端：≤6 字（能耗）与 ≥40 字（啰嗦长句版今日用电量）
目标规模：每类 ≥10 条，从高频 normal 用例衍生
```

**③ gray（阈值灰区）** — 分数带 0.60~0.70 的已知模糊句，单列跟踪，不设硬门槛：

```
- 历史上贴阈值判错的句子（语料评测记录.md 里域分 0.60~0.70 的条目）
- 用途：语料改动后观察这些句子的分数漂移方向，防「按下葫芦浮起瓢」
```

### 2.2 指标定义

| 指标 | 定义 | 建议门槛 |
|---|---|---|
| normal top-1 准确率 | 域内常规问法判对（含子类型）比例 | ≥ 95%（扩写完成后 ≥ 97%） |
| boundary 通过率 | 8 条跨域归属规则用例 | 100%，任何语料改动不得回退 |
| incident 修复线 | 翻车句域分 | ≥ 0.70 |
| **negative 误响应率** | 负样本被判进任何业务域的比例 | ≤ 5%（这是新增的硬门禁） |
| **adversarial 通过率** | 加噪后仍判对 | ≥ 90% |
| other 兜底率 | normal 全量里掉 other 的比例 | ≤ 2% |
| 混淆矩阵 | 每对域 (真实, 误判) 计数 | 重点关注历史冲突对：person.realtime↔count、fire↔security、energy.overall↔realtime、compositive↔device |

### 2.3 报告增强（改 eval_intent.py 输出）

- 按标签汇总（已有）→ 增加 **混淆矩阵打印** 和 **negative/adversarial 两个标签的独立通过率**；
- `--verbose` 模式输出每条 top-3 意图及分数，标出 **margin < 0.02** 的模糊用例；
- 退出码规则保持：boundary/incident/negative 任一失败 → 1（可接 CI）。

## 3. L2 槽位抽取（小幅补充）

在 `tests/test_slots.py` 基础上补负样本组：空串、纯标点、非法时间（「上周32号」）、人名含数字、超长实体名。预期：不抛异常、回退默认值（`_SUBTYPE_FALLBACKS` 口径）。

## 4. L3 会话上下文 / 多轮场景（新增，重点）

### 4.1 场景矩阵

场景脚本统一用「多轮对话 + 每轮断言」描述。断言对象分两种：

- 进程内层：`session_state.get()` 返回的 `IntentState` 字段（module / slots / missing_params / ask_count / unrelated_count / done）
- 事件层（仅 L5）：WS 事件序列

| # | 场景 | 轮次示例 | 断言点 |
|---|---|---|---|
| C1 | 缺参追问闭环 | 「查一下人员位置」→ask缺person_name→「张三」→执行 | 13 域**每域至少 1 条**；done=True、slots 正确 |
| C2 | 追问中答非所问 | 追问人名时答「今天天气不错」 | unrelated_count 递增、再次 ask（re_ask）、`last_question` 更新 |
| C3 | 连续跑题放弃 | 连续 3 次无关回复 | give_up、session_state 被清空、后续输入走全新分类 |
| C4 | 追问中新意图接管 | 追问人名时答「停车场还有多少空位」 | 旧状态清除、按 vehicle_status 全新流程（情况 1.2 takeover） |
| C5 | 同意图子类型切换 | 人员态势 realtime 结果后「今天进了多少人」 | 子类型以本轮为准（回归最近修复的 bug；排查记录案例 13/17） |
| C6 | 省略式追问继承 | 查完 A 后「昨天呢」「那出去的呢」 | 子类型继承命中 `_SUBTYPE_FALLBACKS` 口径：本轮抽出具体子类型以本轮为准，否则继承上轮 |
| C7 | 完成后新查询 | done=True 后直接说新域问法 | 不进追问分支、走情况 2 全新流程 |
| C8 | 会话超时 | 状态 last_update_time 调老 >300s | get() 返回 None、按新意图处理 |
| C9 | 跨会话隔离 | 同 user 两个 session 各自追问 | 状态互不串（slots 不串扰） |
| C10 | 跨用户隔离 | 同 session_id 不同 user | 同上 |
| C11 | 追问轮不吃分类 | 追问态下说一句贴近其他域的话术 | 确认 `handle_reply` 主导（is_waiting 不调 classify），行为与空闲轮分类结果解耦 |
| C12 | 结束语 | 任务完成后「谢谢/拜拜」（≤12 字） | `is_conversation_close` 命中，不触发新意图 |
| C13 | ask_count 上限 | 反复给半截参数 | 追问次数有上限、不死循环 |

### 4.2 落地方式（2026-09-23 落地，含偏差说明）

C1/C4/C5/C6 已落地为 `tests/test_context_scenarios.py`，与原方案的偏差：

- **数据形态**：未用 `tests/scenarios/context_cases.json`，改为模块级 case 元组表 +
  `@pytest.mark.parametrize`（沿用仓库 `test_graphs.py`/`test_handlers.py` 惯例）。
- **不 import app.py**（import 期会初始化 LLM 工厂/上传目录）。C1 与 handler 层行为测的是
  真代码（handler + graph + slots）；接管判定（情况 1.2，app.py:1754-1770）与省略式槽位合并
  （情况 1.5，app.py:1871-1890）内联在 app.py 里够不着，测试内以**规格快照**复刻
  （注释标明源码行号）——**app.py 相应分支改动后测试不会自动红，须人工同步快照**。
- 真实路径由人工冒烟兜底（容器内）：T1 查园区实时人数 → 正常答案；T2「出去的呢」→ 离开人数
  （C5）；T3「昨天呢」→ 昨天离开人数（C6）；T4 查陈强位置 → 追问 → 答「陈强」→ 正常执行
  （C1）；T5 追问人名时改问「停车场还有多少空位」→ 旧任务放弃、车辆域全新回答（C4）。
- app.py 的接缝重构（把接管判定/槽位合并抽成可 import 的纯函数）暂缓（用户裁定：
  只加测试，不动 app.py）；重构后快照可升级为真回归。C7~C13 场景仍待后续补充。

## 5. L4 记忆测试（新增，完全空白）

| # | 用例 | 做法 | 断言 |
|---|---|---|---|
| M1 | 窗口截断 k=10 | MemoryStore 塞 15 轮 | `chat_memory.messages` 只留最近 10 条（5 轮），早期内容不进 `chat_history` |
| M2 | 持久化往返 | save → 新 MemoryStore load | 消息条数、顺序、role、content 完全一致 |
| M3 | 三实现一致性 | 同一用例集分别跑 json / sqlite / mysql persistor | 结果等价（mysql 需要测试库，可用环境变量跳过） |
| M4 | 重启恢复模拟 | persist 后销毁实例、重建 load | 同 M2，覆盖「容器重启后上下文还在」 |
| M5 | graph 口径保存 | `graph_persist_memory` 传 last_turn | 只存本轮 human/ai 消息、role 映射正确；空轮不覆盖历史（`len(messages)>0` 分支） |
| M6 | 会话隔离 | (u1,s1) 与 (u1,s2)、(u2,s1) 互不串 | 各自 load 只见自己的消息 |
| M7 | 损坏容错 | persistor.load 返回垃圾/半条消息 | 不抛异常、返回空历史（store.py 已有 try/except，验证行为） |
| M8 | 窗口外的记忆依赖 | 多轮后问指代性问题 | 明确预期：**窗口外内容本就不该被记住**——这是设计行为记录，不是缺陷 |

落地：`tests/test_memory.py`，persistor 用 `tmp_path` 临时文件/库，不打真 LLM。

## 6. L5 端到端（WebSocket，新增冒烟层）

前置：容器内启动 app，MCP 用 mock 后端（参照 `tests/conftest.py` FakeTool 思路做假 sidecar，或直接连测试环境）。

- 工具：`tools/e2e_ws_client.py`——独立 WS 客户端脚本，按场景发 `{"query": ...}`，收集事件流。
- 断言：
  - **事件序列完整性**：每次应答以 `{"status": "done"}` 收尾（案例 14 回归）；ask 事件带 `missing_params`；
  - E2E1 单域完整流（含追问轮）复用 L3 场景矩阵的 C1/C3/C4/C5；
  - E2E2 **故障注入**：某域 MCP 后端 404/超时 → 该域报 error、其他域不受影响（案例 1 回归的线上版）；
  - E2E3 知识库模式（`mode=kb`）：正常问答、sidecar 未就绪时降级提示；
  - E2E4 断线重连后同 session_id 续问，上下文仍在（依赖 L4 M4 的持久化）；
  - E2E5 asr_ws / doc_ws 各 1 条冒烟。
- 定位： nightly 跑，不进日常 pytest（需要服务在线）。

## 7. L6 LLM 回答质量（抽样 + LLM-as-judge）

适用：知识库问答、文档生成、other 兜底回答。意图/态势类走结构化数据，不必上 judge。

- 抽样集：KB 问答 30 条（其中 5 条知识库**没有**答案的问题，考拒答）、文档生成 5 个模板；
- 评分维度（judge prompt 输出 1-5 分 + 理由）：忠实度（是否脱离检索内容编造）、相关性、拒答正确性；
- 流程：`tools/eval_llm_quality.py` 跑批 → 输出 markdown 报告 → 人工复核 ≤4 分条目；
- 门槛：拒答类 5/5 正确拒答；忠实度均分 ≥ 4。

## 8. L7 性能（补充两项）

`test_performance.py` 已覆盖分类/槽位/图/并发，新增：

- P1 多轮状态内存：模拟 1000 会话 × 10 轮，`session_state.states` 字典占用有界（超时会话被清）；
- P2 记忆持久化耗时：sqlite/mysql persist 单轮 p95 < 50ms（窗口 k=10 下全量重写开销）。

## 9. 落地物清单与执行方式

| 交付物 | 类型 | 依赖 |
|---|---|---|
| `tools/eval_intent.py` 扩 CASES（negative ≥100 / adversarial ≥50 / gray）+ 混淆矩阵输出 | 改造 | 无新依赖 |
| `tests/test_context_scenarios.py`（C1/C4/C5/C6，模块级 case 表，✅ 已落地） | 新增 | 无模型 |
| `tests/test_memory.py` | 新增 | 无 LLM；mysql 用例环境变量门控 |
| `tools/e2e_ws_client.py` + `tests/test_e2e_smoke.py`（手动/nightly） | 新增 | 服务在线 |
| `tools/eval_llm_quality.py` | 新增 | 真 LLM |
| `tests/test_slots.py` 补负样本组 | 改造 | jionlp |

容器内执行（与现有口径一致）：

```bash
# 日常回归（L1~L4，不启服务）
python tools/eval_intent.py                # L1，退出码门禁
python tools/eval_intent.py negative       # 只看误响应
pytest tests/test_context_scenarios.py tests/test_memory.py -v   # L3+L4

# nightly（L5+L6，需服务与 LLM）
python tools/e2e_ws_client.py --suite all
python tools/eval_llm_quality.py --sample 30
```
