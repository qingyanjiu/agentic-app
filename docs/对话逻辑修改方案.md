# 对话逻辑修改方案（多轮追问 + 上下文连贯性）

> 依据：2026-09-15 对话逻辑评审（主流程走查：分类 → 抽槽 → 追问 → 图执行 → 会话状态回写）
> 范围：`agent/intent/handlers/*.py`、`app.py`、`memory/session_state.py`、`graph/*_langgraph.py`
> 结论先行：**主循环骨架完整闭环，但存在 2 个确定性 bug（P0）与 3 类连贯性短板（P1/P2）**

---

## 一、问题总览

| 编号 | 问题 | 影响 | 优先级 |
| --- | --- | --- | --- |
| 1 | 追问轮 slots 合并覆盖子类型（query_type / event_type 被默认值污染） | 确定性 bug：追问完查错工具 | **P0** |
| 2 | 省略式追问拼接后实体抽取查错人 + merged_query 滚雪球 | 确定性 bug："那李四呢"查成张三 | **P0** |

## 二、P0 问题详解与修改方案

### 2.1 追问轮 slots 合并覆盖子类型

**现象（两个典型触发路径）**

1. 问"李四昨天的轨迹" → 缺人名追问 → 答"张三" → `extract_slots("张三")` 无子类型关键词，落回默认 `count` → 覆盖原 `trace` → 最后查的是人数统计。
2. 问"查一下告警详情" → 缺 alarm_id 追问 → 答"第3条" → `event_type` 落回默认 `alarm_list` → 调了无参工具 `security:getSecurityAlarmList`，ID 被丢弃。

**根因**

追问轮 `handle_reply` 用本轮回复**单独**重新抽槽再合并，子类型字段没有"默认值守卫"。各 handler 现状：

| handler | 正则默认值 | 现状 |
| --- | --- | --- |
| `person_status_handler.py` | `query_type="count"` | 守卫值写错：`v != "location"`（:230），等于没守 |
| `security_status_handler.py` | `event_type="alarm_list"` | **无守卫**（:183-186） |
| `canteen_status_handler.py` | `event_type="week_menu"` | **无守卫**（:170-173） |
| `information_status_handler.py` | `event_type="info_view"` | **无守卫**（:168-171） |
| energy / device / vehicle / emergency_fire / meeting / compositive_overview | — | 已正确（如 `v != "count"` / `v != "basic_info"`），不动 |

**修改方案（最小修复）**

统一模式——子类型字段等于本域默认值时不覆盖：

```python
# security_status_handler.handle_reply（canteen / information 同构）
new_slots = await self.extract_slots(query)
for k, v in new_slots.items():
    if not v:
        continue
    # 子类型字段：追问回复无关键词时会落回默认值，不能让它污染原查询
    if k == "event_type" and v == "alarm_list":
        continue
    state.slots[k] = v
```

person 侧把 `v != "location"` 改为 `v != "count"`。

**修改方案（彻底修复，与最小修复二选一或叠加）**

person 的 `extract_slots` 在正则落 `count` 时还会跑 embedding 分类器补判——追问轮的短回复（如人名"张三"）可能被补判成任意子类型并越过守卫。因此追问轮本就不该重判子类型：

- 给 `extract_slots` 加 `is_followup: bool = False` 参数，追问轮传 True 时**跳过分类器补判、跳过子类型正则**，只抽"填空型"字段（人名 / 时间 / 区域 / 告警 ID / 餐次）；
- 子类型变更只允许来自两条正经路径：追问态新意图接管（跨域）、用户完整重新提问（新流程）。

### 2.2 省略式追问：实体查错 + original_query 滚雪球

**现象**

- "张三现在在哪"（done）→ "那李四呢" → 拼接串 `"张三现在在哪 那李四呢"` 整体抽槽 → `extract_person_name` 按固定名单顺序取第一个命中（`slots.py:307-310`）→ 永远返回张三。
- 拼接串存回 `original_query`（`start_module_flow` 直接以 merged_query 建状态），连续追问"昨天呢/上周呢"后原话越来越长，embedding 分数被稀释。

**设计原则**

> **拼接串只用于意图分类（embedding 需要完整语义）；slot 抽取用本轮输入；本轮没抽到的字段从上一轮状态继承。**

**修改方案**

`app.py` 情况 1.5 改为"继承式启动"，`start_module_flow` 增加可选参数：

```python
# app.py 情况 1.5
merged_query = f"{active_state.original_query} {query}"   # 只喂分类器
merged_intent = (await classify_intent(merged_query))["intent"]
if merged_intent in MODULE_HANDLERS:
    handler = MODULE_HANDLERS[merged_intent]()
    slots = await handler.extract_slots(query)            # ① 只用本轮输入抽槽
    if merged_intent == active_state.module:              # ② 同域继承未抽到的实体槽
        for k in ("person_name", "area", "alarm_id", "meal"):
            if not slots.get(k) and active_state.slots.get(k):
                slots[k] = active_state.slots[k]
    # ③ original_query 传首轮原话，不回写拼接串
    await start_module_flow(websocket, query, merged_intent,
                            user_id, session_id,
                            slots=slots,
                            original_query=active_state.original_query)
```

`start_module_flow` 对应调整：`slots` / `original_query` 可选传入，缺省时维持现状（新流程从 query 抽取）。注意 ② 只继承实体槽，**时间不继承**——"那上周呢"的时间必须来自本轮。

### 2.3 省略式追问路由优先级对调

**现象**

拼接分支仅在 `top_intent == "other"` 时触发（`app.py:1289`）。"昨天呢"这类短承接语若碰巧在 embedding 上过某域 0.65 阈值，会**优先走全新流程**，然后因缺人名反问"请问查谁？"——用户几秒钟前刚说过查谁，体感最伤。

**修改方案**

在 top_intent 计算之后、if/elif 分支之前插入预处理（避免破坏现有 elif 链）：

```python
# top_intent 计算之后：
ellipsis_state = None
if active_state is not None and active_state.done and len(query.strip()) <= 6:
    merged_intent = (await classify_intent(
        f"{active_state.original_query} {query}"))["intent"]
    if merged_intent in MODULE_HANDLERS:
        top_intent = merged_intent          # 短输入以拼接分类结果为准
        ellipsis_state = active_state       # 标记：情况 2 分支改走 §2.2 继承式启动

# 情况 2 各分支内：ellipsis_state 存在 → 用继承式启动；否则维持现状
```

拼接未命中业务域时 `top_intent` / `ellipsis_state` 均不变，行为与现状完全一致——**对老 query 零影响，只收紧短承接语的路径**。

## 三、P1 修改方案

### 3.1 对话历史注入 LLM（对比类追问的基础）

现状：LLM 组织回答只看 `original_query` + 本次 MCP 原始数据（如 `graph/security_status_langgraph.py:111-117`），没有上一轮答案，"那上周呢"答不出"比昨天多了 3 条"。

1. `memory/session_state.py` 的 `IntentState` 增加：

```python
# 最近几轮问答（最旧在前），仅保留最近 3 条，控制 token
history: list = field(default_factory=list)   # 元素 {"query": str, "answer": str}
```

2. 各 `run_xxx_graph` 在成功产出 answer 后追加（超过 3 条移除最旧）。
3. `_llm_format_xxx_result` 的 prompt 增加历史段与新约束：

```text
对话历史（供指代与对比参考，数字不得引用此处）：
用户：今天告警多少条？
助手：今日告警共 12 条，其中…
要求新增：若用户本轮是"那上周呢 / 前天呢"类承接问法，回答需与上一轮自然衔接
（如指出上升/下降），但所有数字必须来自本次返回数据。
```

> 顺带：10 个 `run_xxx_graph` 是复制粘贴的同构代码，本次至少把"追加 history + 发送事件"抽成公共 helper；完全合并为 `run_module_graph` 记为可选重构，不阻塞本方案。

### 3.2 追问态跨域接管范围扩大

现状：接管判断只在 `re_ask` 分支（`app.py:1215-1231`）。若 `is_related` 关键词启发式把跨域新问题误判为"相关"，直接 continue 本域流程，新意图被吞。

方案：在 `continue` 分支执行图前，若**本轮回复较长（≥8 字，像完整新问题）且当前仍缺参**，补跑一次 `classify_intent(query)`，跨域且过阈值 → 按情况 2 接管。短回复（明显是补参，如"张三"、"近一周"）不跑分类，控制额外开销。

## 四、P2 修改方案

### 4.1 "上周 / 上月"时间口径

`security_status_handler.handle_reply` 情况 A（person 同构）里 `elif "周" in q` 会把"上周"当近 7 天。改法：在通用"周/月"匹配**之前**先判"上周/上月"，映射为上一自然周（周一 00:00 ~ 周日 23:59:59）/ 上一自然月，与 `parse_time_slot` 现有口径保持一致。

### 4.2 错误事件脱敏

各图 `call_tool` 异常分支（如 `graph/security_status_langgraph.py:430-436`）当前把 `{str(e)}\n{tb}` 原样发给前端。改为：前端只发"查询失败，请稍后再试"，完整异常与堆栈进 `logger.error`。

### 4.3 会话状态外置（备忘，暂不实施）

`SessionStateManager` 为进程内存 dict（`memory/session_state.py:50`），重启失忆、多副本不共享。单机部署可接受；上集群前迁移 Redis（key 结构 `user_id:session_id` 可原样复用），届时 `IntentState` 需可 JSON 序列化。
