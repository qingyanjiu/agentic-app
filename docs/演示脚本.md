# 项目能力演示脚本

> 目的：向领导完整展示本项目的**对话能力、记忆能力、工作量与可复用性**。
> 原则：所有演示问法均对应真实存在的工具与接口，口径以 `docs/Java-MCP接口清单与Mock返回格式.md` 为准；
> 预期回复中的具体数字为 mock 口径示例，**以现场实际返回为准**。
> 更新日期：2026-09-22

---

## 〇、演示前准备清单

| 事项 | 说明 |
|---|---|
| 预热会话 | 演示前 10 分钟把全部问法跑一遍；会话状态超时 5 分钟（`SessionStateManager timeout=300s`），避免现场上下文过期 |
| Debug 模式 | 第二幕前开启 `enable_debug=True`，流式输出会带节点信息；演示第四幕后关闭，避免干扰 |
| 评测报告 | 提前跑好 `tools/eval_intent.py`，**截图或导出表格**放进材料；现场只翻 `docs/语料评测记录.md` 原文档，不现跑 |
| 录屏备份 | 全程录屏，语音/现场不稳定时切录屏 |
| 副屏挂图 | 数字总览页（见第二节）常驻副屏，随时回指 |
| 主演示域 | 设备查询、能源、会议、人员态势为最稳域；冷门域不上现场 |

## 二、开场：工作量数字总览（1 分钟）

> 这个项目目前包含：
> - **18 条** LangGraph 业务管线，覆盖人员、车辆、能源、消防、周界、会议、食堂、设备、巡检、信息发布、综合态势等 **12+ 个业务域**
> - **13 个** MCP 端点、**68 个**工具的标准接入
> - 意图识别引擎单文件 **3872 行**（规则 + 语料），本轮扩写已产出 **743 条**分域语料（能源一域 253 条），目标 12 域 × ≥250 条
> - 核心代码约 **2.4 万行**，配套 **7 个测试模块**（意图 / 处理器 / 管线 / MCP 加载 / 性能 / 槽位）与 **7 份工程文档**

**话术**：
> "68 个工具、12 个域，每个域都是同一套框架长出来的——工作量和可复用是同一件事。"

**演示动作**：副屏展示数字总览页（PPT 或架构图），后续每一幕结束可回指对应数字。

## 三、第一幕：多轮追问补参 —— 设备查询（2 分钟）

**展示能力**：要素缺失主动追问、模糊/精确双模式检索、查询结果被后续对话继承。

### 操作与预期对话

| 轮次 | 用户输入 | 预期行为 / 回复口径 |
|---|---|---|
| 1 | 帮我查一下设备 | 要素缺失 → 主动追问："请问您要查询什么设备？可以告诉我设备名称或编号" |
| 2 | 枪机 | `device_query:listDevice` 模糊匹配 → 返回列表，如"A栋枪机（CY-HIK-JK-001-0001），位置：园区/A栋/3楼，状态：启用" |
| 3 | 它的负责人是谁？ | "它"继承刚查到的设备 → `getDeviceDetail` 取 `personInChargeName`：张三，所属：安防部 |
| 4 | 查一下编号 CY-HIK-JK-001-0001 | 精确命中 → 返回完整档案（位置 / 负责人 / 维护状态） |

**亮点话术**：
> "用户不需要按格式填表。问得太泛，系统缺什么主动问什么；问得具体，直接精确命中。追问有次数上限和无关回复识别，不会死循环。"

**内部依据**：`graph/reactive_pipeline.py`（缺参追问流程）、`agent/intent/slots.py`（区域别名词典：A座→A栋归一；员工名单匹配）。

**工作量标注**：此处回指副屏"68 个工具、13 个端点"——设备查询只是其中一条标准接入。

## 四、第二幕：跨域路由 + 上下文继承（2 分钟）

**展示能力**：12+ 域意图路由广度；"那"字类上下文继承。

### 操作与预期对话

| 轮次 | 用户输入 | 命中域 / 工具 | 预期回复口径 |
|---|---|---|---|
| 1 | 现在园区有多少人？ | person_status | 实时在园 12 人，今日进入 30 人、离开 25 人 |
| 2 | 停车位还剩多少？ | vehicle_status | 总 200，已用 120，剩余 80 |
| 3 | 那用水排名呢？ | **"那"继承能源域** → water_usage_ranking | A栋 200 吨领先… |
| 4 | 这周食堂有什么菜？ | canteen（getWeekMenu，走 data 包装特殊解析） | 周一早餐番茄炒蛋 5 元/份… |

**亮点话术**：
> "连续四个问题命中四个不同业务域。第三问只有六个字，系统要自己判断'那'指能源——这是会话内上下文继承。"

**内部依据**：`agent/intent/classifier.py`（3872 行意图引擎）、各域 `graph/*_langgraph.py`（18 条管线）。

**工作量标注**：此处回指"18 条管线、12+ 域、意图引擎 3872 行、扩写语料 743 条"。

## 五、第三幕：会议室场景 —— 实体继承 + 时间解析（1.5 分钟）

**展示能力**：指代消解（"它"）、自然语言时间要素解析。

### 操作与预期对话

| 轮次 | 用户输入 | 预期行为 / 回复口径 |
|---|---|---|
| 1 | 第一会议室现在有人用吗？ | `meeting:getMeetingRoomStatus` → "占用" |
| 2 | 它今天下午还有几场会？ | "它"继承"第一会议室" → `getRoomMeetListByDay`（jionlp 解析"今天下午"为 startTime/endTime）→ 周会 09:30-10:30，预约人张三 |
| 3 | 顺便看下这个月的会议统计 | `meeting:getMeetingStatistics` → 2026-09 共 42 场，平均时长 55 分钟 |

**亮点话术**：
> "'它今天下午'——五个字里系统完成了指代消解加时间要素抽取，这是对话体验的关键细节。"

**内部依据**：`agent/intent/slots.py`（jionlp 时间解析 + 预热）、`graph/meeting_status_langgraph.py`。

## 六、第四幕：跨会话记忆（1.5 分钟）

**展示能力**：会话内记忆（前三幕已证）+ **跨会话长期记忆**（有真实数据背书）。

### 操作与预期对话

1. 现场**新建一个会话**，只输入两个字：
   > **用户**：合肥
   > **系统**：合肥今天（2026年9月20日）的天气是大暴雨 🌧️…

   （此条为 `memory_store.json` 中的真实历史记录，演示前可先验证一遍）
2. 当场打开 `memory_store.json`：按 `user_id + session_id` 持久化，跨会话可取回。

**亮点话术**：
> "新会话只说'合肥'两个字，系统知道要查天气——因为它记得这位用户上次在查什么。记忆不是聊天记录，是按用户和会话两级组织的结构化状态，持久化层支持 json、mysql、sqlite 三种实现，切换零改动。"

**内部依据**：`memory/`（4 种持久化实现：`memory_persistor.py` / `_json` / `_mysql` / `_sqlite`）、`memory/session_state.py`（意图状态含槽位、缺失参数、追问计数、超时清理）。

**⚠ 兜底**：若现场"合肥"未接上，切录屏；话术改为演示 `memory_store.json` 文件内容本身。

## 七、第五幕：工程环节可视化 —— Debug 模式重放（1 分钟）

**展示能力**：把"一行回答背后的工程量"拆给领导看。

### 操作

开启 `enable_debug=True`，把第二幕的"那用水排名呢"重新问一遍，让领导看到节点流转：

```
文本纠正 → 意图识别(3872行引擎) → 域路由(18选1) → 工具选择(68选1)
→ 参数解析(时间/区域归一) → 工具调用 → 结果评估节点 → 生成回答
```

同时指前端工具调用卡片（web/js/app.js 的工具展示 + displayName 映射）：

**亮点话术**：
> "用户说'那'，系统要自己想明白是哪个域、哪个工具、哪些参数继承自上文——纯规则系统做不到。前端也能实时看到调用了哪些工具，不是套壳聊天，是真的在调度 68 个工具。"

**演示后立即关闭 debug 模式**。

## 八、收尾 A：质量是管出来的 —— 评测体系（1.5 分钟）

**操作**：翻 `docs/语料评测记录.md`（不现跑评测）。

展示三个要点：

1. **三类用例标签**：`normal` 常规问法 ｜ `boundary` 边界锁 ｜ `incident` **线上翻车句**
2. **硬规则**：每次语料改动前后各跑一次评测，**任何改动不得使基线回退**
3. **闭环案例**：线上翻车句"今天园区能耗情况怎么样？"被判 other，根因（语料薄 + 泛化问法无域核心词锚定）在评测中精确复现并闭环；基线 75% 起步持续治理

**话术**：
> "我们不靠感觉说'效果不错'。每一次语料改动都有量化前后对比，翻过车的句子全部变成回归用例锁死。"

**配合动作**：投出提前跑好的 12 域准确率表格截图。

## 九、收尾 B：唯一产出物闭环 —— Word 报告生成（1 分钟）

> **用户**：把刚才查到的设备情况、能耗和会议安排汇总成一份巡检报告
> **系统**：`doc_gen_pipeline` 生成 Word 文档，前端提供下载

**话术**：
> "对话的终点不只是回答，还可以直接交付文档——查询、分析、汇报一次完成。"

**内部依据**：`graph/gen_doc_pipeline.py`、`doc_tools/word_gen_json.py`（Word 样式模板可配置）。

## 十、可复用性总结话术（30 秒）

> "项目分两层：**框架层**——多轮对话管理、追问补参、双层记忆、意图路由、动态工具生成；**业务层**——12 个域的工具与语料。
> 新业务接入成本 = **一份领域语料 + 一个 API/MCP 注册**，框架代码零修改。
> 目前 68 个工具、13 个端点就是这么长出来的，这就是可复用的证明。
> 现在没有的能力不是框架做不到，是业务接口还没开放——比如写操作，框架支持，工具就是普通函数，业务方决定何时开放。"

## 十一、风险与兜底

| 风险 | 应对 |
|---|---|
| 意图识别现场翻车 | 主演示域只用设备/能源/会议/人员四个最稳域；准备录屏随时切换 |
| 会话状态超时（5 分钟） | 每幕开始前若间隔较久，先快速重问一句上幕问题热身 |
| "合肥"记忆未接上 | 切录屏；或直接展示 `memory_store.json` 文件内容 |
| 领导问"能不能办事（写操作）" | 标准回答见第十节末段：框架支持，业务接口未开放 |
| 领导问"是不是就调了个大模型 API" | 指第五幕节点链 + 第八节评测体系：工程量在模型外面 |
| 领导问"换个园区还能用吗" | 指动态工具生成（新 API 不写代码注册）+ 记忆层 4 种存储可切换 + MCP 标准接入 |
