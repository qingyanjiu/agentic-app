> 本文是**唯一的架构入口文档**。历史方案已归档删除（旧的 LangGraph 13 张业务图、gen_doc、语音链路

## 1. 一句话定位

一个**多域问答智能体**：接住园区业务侧 13 个域（人员/安防/食堂/车辆/信息发布/能源/会议/消防/
周界/孪生巡检/设备查询/设备状态/综合概览）的自然语言提问，调 MCP sidecar（Java）拿数据，再用
模板或模型组织成人话回答；顺带承载 UE 3D 场景控制的下发通道。

技术栈：FastAPI + WebSocket、openai SDK、MCP 官方 Python SDK、sentence-transformers（意图向量）。
**没有 LangChain，没有 LangGraph。**

## 2. 请求总流程

```
浏览器 / UE 前端
   │  ws  {"query": "...", "mode"?: "loop|legacy|scene|kb"}
   ▼
app.py  agent_ws()
   ├─ ① mode=kb        → 「知识库问答暂未接入」（只留 KnowledgeMcpClient 检索入口）
   ├─ ② mode/灰度=loop → agent/loop/ws_bridge.handle_chat()   ← 主链路
   │      ├─ L1 预路由命中 → 确定性直出（模板 + 结构化清单）
   │      └─ L2 loop agent → 模型自选工具 → 答案（全程流式）
   ├─ ③ 场景分流命中    → agent/scene_control（顺序编排，非图）
   └─ ④ 都没接住        → 一句话兜底（answer + done）
   ▼
MCP sidecar（Java，:2223）   /mcp/{personStatus,securityStatus,...,devicequery,scene,knowledge}
```

三处关键设计（改动前先看）：

1. **双通道而非全 loop**：L1 预路由直连保延迟（模板化、确定性强），L2 loop 兜跨域/低置信。
2. **判定权分层**：语言理解（这句话想问什么）可以交给模型；**状态机与下发参数（选哪个
   tag、要不要继续追问）必须留在确定性代码**。
3. **一轮对话必须有结尾**：任何分支都必须发 `done`，否则前端永久转圈（见 `docs/问题排查记录.md` 案例 14）。

## 4. 入口层 `app.py`

| 端点 | 说明 |
|---|---|
| `WS /chat/{user_id}/{session_id}` | 唯一对话入口，收发 JSON |
| `POST /upload/image` | 图片上传（前端多模态预留） |
| `GET /static/*`、`/reports/*`、`/uploads/*` | 静态资源 |

一轮消息的处理顺序（`agent_ws`）：

1. 收包走独立 task + `asyncio.Queue`，主循环只从队列取 → 本轮在跑时也能读到 `type=stop`；
   停止只取消 `Queue.get()`，**绝不 cancel 挂着的 `receive_text()`**。
2. `mode=kb` → 明确提示未接入，`answer + done`。
3. 灰度判定 `roller.decide(user_id, session_id, payload.mode)`：
   - 命中且有场景追问态 → 优先交回场景通道（否则模型拿不到上一轮候选清单）；
   - 命中 → `ws_bridge.handle_chat`，异常一律回落（日志带原话）。
4. 场景分流（`mode=scene` / 场景追问态 / 场景意图与业务意图竞速）。
5. 都没接住 → 一句话兜底 + `done`。

## 5. Loop Agent（`agent/loop/`）

### 5.1 三级分流

| 级别 | 谁做 | 何时 | 代价 |
|---|---|---|---|
| L0 | `agent/intent` + `router` | 显式场景/模式、追问态 | 一次向量分类 |
| L1 | `router` + `domains/*.route_plan` | 分类置信 ≥ 阈值且子类型明确 | **不调模型**，模板直出 |
| L2 | `LoopAgent` | 跨域、低置信、需要多步 | 模型循环（可多轮工具） |

阈值 0.75 来自语料准确率拐点，不是拍脑袋；要调先跑 `tools/eval_intent.py`（见 `docs/测试方案.md`）。

### 5.2 域内口径（`domains/`）

每个域一个模块，声明式给出 `CONFIG`（域 → 子类型 → MCP 工具）与可选钩子：

```python
CONFIG = _generic.QueryDomain(
    name="device_query",
    tool_map={...},          # 子类型 → 工具名
    default_type="list",     # 未识别子类型时的兜底工具
    empty_hint="...",        # 空结果话术（禁止模型猜"服务异常"）
    formatter=...,           # 工具原始返回 → 人话（如 ECharts JSON → 统计文本）
)
```

`_generic.QueryDomain` 是 frozen dataclass；测试里改字段要 `object.__setattr__`。

### 5.3 结构化清单（`entities.py` → `list` 事件）

设备的「清单」由**工具层产出**，不经模型：

- `ToolOutcome.entities` → `PipelineResult.entities`，L1 直出后补发 `list`，L2 由内部事件翻译；
- 文本仍保留（历史记录 + 旧前端兜底），靠 `text.startsWith(list.title)` 去重；
- **契约**：`_format_rows` 首行 = `_summary() + "："`，`list.title` = `_summary()`，两者必须互为前缀。

前端接口见 `docs/前端对接-list事件.md`。

### 5.4 工具执行与校验

`runtime.py` 用**官方 mcp SDK**（不再用 langchain_mcp_adapters）；`validate.py` 做参数白名单与
压缩；`govern.py` 在回答前做口径纠正（例如"设备类型统计"直接从工具结果组织，不让模型贴 JSON）。

## 6. 场景控制（`agent/scene_control.py`）

- 原来是 `graph/scene_control_langgraph.py`，现在**去掉了 LangGraph**：链只有一条
  `init → plan_action →(条件)→ ask_param / give_up / call_tool → finalize`，用顺序调用 +
  手写状态归并（`_apply`）即可，对外仍是 `build_scene_control_graph(...).ainvoke(state)`。
- `/mcp/scene` 是 `direct_client`：**每个请求都要带 `X-Session-Id`**，动作类**不能重试**。
- 快通道：确定性指令（切楼层、重置视角等）走规则，不调模型；其余交模型选工具并填参数。
- 设备名 → 点位 tag 的解析在 `agent/loop/scene_resolve.py`（候选清单 + 序号解析 + 追问出口规则）。
- 合同细节（工具清单、参数枚举、UE 侧对接）见 `docs/UE场景控制接入说明.md`。

## 7. 意图层（`agent/intent/`）

- `classifier.py`：向量相似度 + 关键词规则，输出 `{intent, subtype, confidence}`；13 域 69 子类型。
- `slots.py`：楼层/区域/设备名/时间槽位；区域同义词用**显式小表**（如 食堂↔餐厅），
  不复用 `AREA_DICT` 全量（「入口」「门岗」太泛会捞错设备）。
- 分类器**只负责语言理解**；哪种工具、是否追问由 `loop/router` + `domains` 决定。

### 7.1 子类型口径约定（改语料 / 加子类型前必读）

这些约定锁在测试里（`tests/test_slots.py`、`tests/test_intent_classification.py`），改语料会直接红：

1. **`compositive_overview` 只留两个独占子类型**：`basic_info`（园区面积/IoT 设备总数/园区概况）
   与 `device_health`（设备健康度/健康分总览）。人车/能耗/会议/安全指数的问法一律归原域，
   严禁收进总览语料——否则会把别的域中心向量拉过去（历史「吸铁石」问题）。
2. **`device_health` 只收"健康度/健康分"总览口径**；分类健康度（消防/空调/安防/广播/门禁 + 健康）
   归 `device_status.category_health`。
3. **总览语料尽量带"总览/概况/整体"限定词**，拉开与设备态势的距离。
4. **`emergency_aialert` 已并入 `security_status`**（`security_status` 的 `ai_alert` /
   `ai_inspection` / `inspection_trend` 三个子类型），不再有独立域。
5. **`device_query` 是资产库台账口径**：`syncSource` 八类 0门禁 1道闸 2梯控 3监控 4入侵报警
   5广播 6水表 7电表；只报编码、不带"设备/台"的短问法（如「MH-001的详情」）过不了顶层阈值，
   属已知取舍，不靠调阈值解决。

## 8. MCP 接入层（`mcp_client/`）

- 地址：`MCP_BASE_URL`（环境变量）> yaml 顶层 `mcp_base_url`；各条只写路径（`/personStatus`），
  读取时拼成完整地址（`mcp_config.resolve_url`）。
- 15 个 server 条目，其中 `scene`、`knowledge` 标 `direct_client: true`：
  不走动态发现，由专属客户端直连。
- `devicequery` 是**动态发现试点**：`discover.PILOT_SERVERS` 只列它，运行时用 `tools/list`
  自动注册工具（`devicequery__*`），避免 24 个工具手工维护；重名的 5 个工具与 `/mcp/device` 返回一致。
- 工具清单与字段口径见 `docs/Java-MCP接口清单与Mock返回格式.md`。

## 10. 模型层（`models/llm.py`）

唯一模型配置，全部走环境变量（空串按未设置处理）：

| 变量 | 取值 | 默认 |
|---|---|---|
| `LLM_TYPE` | `openai` / `ollama` | `openai` |
| `LLM_BASE_URL` | 接口地址 | `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 模型名 | `deepseek-flash` |
| `LLM_API_KEY` | 密钥（缺省回退 `OPENAI_API_KEY`） | — |
| `LLM_REASONING_EFFORT` | `low`/`high`/`max`（`off` = 不传） | `low` |
| `LLM_THINKING` | `enabled`/`disabled` | `disabled` |

对外只有一个 `ChatClient`：`await llm.ainvoke(prompt) -> Completion(.content)`，
外加 `model_name / openai_api_base / openai_api_key` 三个属性供 `ws_bridge.build_pipeline` 复用。

## 11. 前端

- `web/`：自带调试页，事件协议的最新实现（也用来验 L1/L2 差异）。
- `tf_park_ue`（独立仓库）：正式前端，支持 `list` 结构化清单、停止按钮、流式「过程稿」与最终回答。

### WebSocket 事件协议

| type | 语义 |
|---|---|
| `answer` | 追加一段正文（流式分块、最终答案都发这个） |
| `ask` | 追问，读 `question` |
| `tool` | 工具调用轨迹（过程稿） |
| `list` | 结构化清单，见 `docs/前端对接-list事件.md` |
| `error` | 错误提示 |
| `{"status":"done"}` | 本轮结束（必发，缺了前端转圈） |

## 14. 已知限制（改之前先读）

1. **会话不落库、不跨进程**：重启失忆；`session_state.states` 过期只清被访问的 key（真泄漏）。
2. **上下文预算按字符估**，不是 token；长工具结果靠 `validate.compress_tool_messages` 压。
3. **`countByFloor` 口径与台账不一致**（14 台 vs 579 台），后端待确认；`deviceType` 参数当前不生效。
4. **`getEquipClass` 合计 391 ≠ 台账 579**（饼图与台账是两套口径，回答时不要混用）。
5. **`/mcp/device` 与 `/mcp/devicequery` 有 5 个重名工具**，L2 可能绕过 `device_status.formatter` 贴 JSON。
6. **知识库只留检索口**：`KnowledgeMcpClient.call_tool("ragflow:searchKnowledge", ...)`，问答编排以后再加。
