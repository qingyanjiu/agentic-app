## 1. 系统全景

系统由 **两个部署单元 + 三类外部依赖** 组成：

- **mcp-sidecar**：聊天网关、MCP 服务端、场景动作调度。
- **agentic-app**：聊天后端（Loop Agent / 旧版 LangGraph 灰度）、意图识别、MCP 客户端。
- **外部依赖**：Platform 平台（业务数据 + 登录态）、RAGFlow（知识库）、LLM 服务（OpenAI 兼容 API）。

```text
                    内网 / Nginx（如启用）
                             │
                             ▼ 127.0.0.1:2222
  ┌──────────────────────────────────────────────────────────────────────────────┐
  │ mcp-sidecar（Spring Boot 3.5 / Spring AI 1.1.8 / MCP SDK 0.18.4）            │
  │                                                                              │
  │  2222（宿主机回环，不对外）              2223（仅 Docker 内网）              │
  │  ├─ /llm/**、/ws/**                      ├─ /mcp/**（17 端点 / 113 工具）    │
  │  ├─ AuthHandshakeInterceptor             └─ McpApiKeyFilter                   │
  │  ├─ ProxyWebSocketHandler                                                    │
  │  ├─ SceneWebSocketHandler                                                    │
  │  └─ LLMChatLimiter                                                           │
  │                                                                              │
  │  9970（仅容器内）：/actuator/** 健康检查                                     │
  └──────────────────────────────────────────────────────────────────────────────┘
          │ WS 代理（/chat、/gen_doc）                    │ MCP tools/call
          ▼                                               ▲
  ┌───────────────────────────────────────────────────────┴──────────────────────┐
  │ agentic-app（FastAPI，8001，仅 Docker 内网）                                 │
  │  ├─ WS /chat/{user}/{session}：主对话（Loop / 旧图灰度 / 场景分流）          │
  │  ├─ WS /gen_doc、WS /asr、POST /upload/image                                 │
  │  ├─ agent/loop：LoopAgent + ToolRegistry + MCP Toolbox                       │
  │  ├─ agent/intent：embedding 分类 + 正则槽位 + 追问 Handler                   │
  │  └─ mcp_client：mcp_config / mcp_loader / runtime / direct clients           │
  └──────────────────────────────────────────────────────────────────────────────┘
          │ HTTP                                  │ HTTPS
          ▼                                       ▼
   Platform :9500 / RAGFlow :9380            LLM 服务（OpenAI 兼容）
```

### 1.1 组件职责

| 组件 | 职责 | 端口 |
|---|---|---|
| 聊天前端 / UE 页面 | `/llm/chat`、`/llm/gen_doc`、`/ws/scene` | — |
| **mcp-sidecar** | 鉴权、限流、WS 代理、场景调度、17 个 MCP 服务端 | 2222（回环）、2223（内网）、9970（容器内） |
| **agentic-app** | 意图识别、Loop Agent、旧图灰度、MCP 客户端、流式回答 | 8001（仅内网） |
| Platform | 业务数据 API、用户 token 校验 | 9500（sidecar 访问） |
| RAGFlow | 知识库检索 | 9380（sidecar 访问） |
| LLM 服务 | 大模型推理 | 由 `LLM_BASE_URL` 决定 |
| Redis | compose 可选服务（`--profile redis`），当前未接入业务 | — |

### 1.2 端口与网络边界

| 端口 | 发布方式 | 允许路径 | 用途 |
|---|---|---|---|
| `2222` | **只绑 `127.0.0.1`，不对外**；需要外部入口时由同机 Nginx 反代 | `/llm/**`、`/ws/**` | 聊天、文档生成、场景页面 WS |
| `2223` | `expose` 到 Docker 网络，不发布 | `/mcp/**` | agent 调用 MCP 工具 |
| `9970` | 仅容器内 | `/actuator/**` | 健康检查 |
| `8001` | `expose` 到 Docker 网络，不发布 | `/chat/**`、`/gen_doc/**`、`/asr/**` | agent 内部服务，只允许 sidecar 访问 |

端口隔离由 `EndpointPortGuardFilter` 无条件执行，未登记端口默认拒绝：

- 2222 只放行 `/llm/**`、`/ws/**`；访问 `/mcp/**` → 404；
- 2223 只放行 `/mcp/**`；访问 `/llm/**`、`/ws/**` → 404；
- 9970 只放行 `/actuator/**`；
- 其它端口 → 404。

`/mcp/**` 还有第二层鉴权 `McpApiKeyFilter`：每个请求必须带
`Authorization: Bearer <MCP_API_KEY>` 或 `X-MCP-API-Key: <MCP_API_KEY>`；
未配置 key 时全部 401。2223 监听地址由 `mcp.internal-address` 指定：
本地默认 `127.0.0.1`，容器内由 compose 注入 `MCP_INTERNAL_ADDRESS=0.0.0.0`。

### 1.3 部署拓扑

```text
宿主机
├── Nginx（可选，外部入口；TLS 在这一层终止）
│     └── proxy_pass http://127.0.0.1:2222   /llm/、/ws/scene
│
└── Docker 网络 ai-agenic-network
    ├── mcp-sidecar
    │   ├── 127.0.0.1:2222 → /llm/**、/ws/**      （仅宿主机回环）
    │   ├── expose 2223   → /mcp/**               （agent 访问，需 API Key）
    │   └── expose 9970   → /actuator/**          （容器内 healthcheck）
    ├── agentic-app（expose 8001）
    │   ├── /chat/**、/gen_doc/**、/asr/**         （只允许 sidecar 访问）
    │   ├── sidecar ──WS 代理──▶ agent
    │   └── agent ──MCP tools/call + Bearer key──▶ sidecar:2223
    └── redis（--profile redis，可选；当前未使用）

sidecar ──HTTP──▶ Platform :9500 / RAGFlow :9380
agent   ──HTTPS──▶ LLM 服务
```

> 生产部署不把 2222 发布到局域网/公网；如果确实需要外部访问，只通过 Nginx
> 的 443 入口反代，并保证 Nginx access log 不记录 query（`?token=`）。
> 本地调试可临时把 compose 的 `ports` 改为 `2222:2222`，但不要在生产这样做。

## 2. 核心数据链路

| 链路 | 发起方 | 协议 / 端口 | 接收方 | 用途 |
|---|---|---|---|---|
| A. 聊天问答 | 前端 | WebSocket / 2222 | sidecar → agent | 对话、文档生成 |
| B. MCP 查询 | agent | MCP Streamable HTTP + API Key / 2223 | sidecar → Platform | 实时业务数据 |
| C. 场景动作下发 | agent | MCP Streamable HTTP + API Key / 2223 | sidecar → UE 页面 | 切楼层、聚焦等动作 |
| D. 场景状态同步 | UE 页面 | WebSocket / 2222 | sidecar | 会话归档、状态、回执 |

### 2.1 A：聊天问答链路

```text
  前端                            sidecar:2222                        Platform:9500                    agent:8001
  │                               │                                   │                                │
  │─ WS /llm/chat?token&userId ──▶│                                   │                                │
  │                               │ 提取 token / userId / sessionId   │                                │
  │                               │──── GET /llmChat/auth ───────────▶│                                │
  │                               │◀─── {status:1, data:200|401} ─────│                                │
  │                               │ data≠200 → UNAUTHORIZED + 关闭     │                                │
  │                               │ 限流 tryToChat（默认 10）          │                                │
  │                               │──── WS /chat/{userId}/{sessionId} ────────────────────────────────▶│
  │                               │◀──────────────── 101 Switching Protocols ────────────────────────│
  │────────── 用户消息 ──────────▶│────────────────── 原样转发 ───────────────────────────────────────▶│
  │                               │                                   │      Loop Agent / 旧图推理     │
  │                               │◀───────────────── 流式回答 ────────────────────────────────────────│
  │◀───────── 流式回答 ───────────│                                   │                                │
```

关键点：

- 浏览器原生 WebSocket 不能设自定义头，token 优先取 `Authorization`，回退 query `token`。
- Platform `/llmChat/auth` 的鉴权结果在响应 **`data` 字段**（HTTP 状态通常都是 200），sidecar 只认 `data=200`。
- 并发限制是进程内 `Semaphore`（默认 10），每个 WS 连接占一个许可，断开释放。
- sidecar 是 WS 客户端，agent 是 WS 服务端；sidecar 只透传，不解析业务消息。

### 2.2 B：MCP 业务查询链路

> 所有 MCP 请求都带 `Authorization: Bearer <MCP_API_KEY>`（或 `X-MCP-API-Key`）；
> 缺失/不匹配在进入业务逻辑前返回 401。

```text
  agent (MCP Client)                    sidecar:2223                                Platform:9500
  │──────────── initialize ────────────▶│                                           │
  │◀─── Mcp-Session-Id + serverInfo ────│                                           │
  │──────────── tools/list ────────────▶│                                           │
  │◀─────────── 工具定义列表 ───────────│                                           │
  │──────────── tools/call ────────────▶│                                           │
  │                                     │ 路由到 @McpTool                          │
  │                                     │ 无平台 token / 已过期时：                │
  │                                     │──── GET /noLogin/getLoginInfo ──────────▶│
  │                                     │◀─── ssl / sslType / publicKey ───────────│
  │                                     │──── POST /login（RSA 加密） ────────────▶│
  │                                     │◀──────── {data:{token}} ─────────────────│
  │                                     │──── 业务接口 + Bearer ──────────────────▶│
  │                                     │◀──────── {status,msg,data} ──────────────│
  │◀──────── tools/call result ─────────│                                           │
```

关键点：

- sidecar 用 **服务账号** 登录 Platform，token 缓存在 `AbstractApiCallService.tokenMap`（默认 30 分钟），与用户登录态无关。
- 平台开启 `sslLogin=on` 时用公钥做 RSA 加密；拿不到公钥默认失败，不静默回退明文（`PLATFORM_ALLOW_PLAINTEXT_LOGIN` 必须显式开启）。
- 每个 MCP 端点独立维护 `Mcp-Session-Id`；`/mcp/scene` 额外要求逐请求 `X-Session-Id`。
- `mcp.mock` 机制保留，但当前 `@MockData` 注解均已注释，全部走真实平台接口。

### 2.3 C：场景动作下发链路

```text
  UE 页面                               sidecar                                 agent
  │─────────── WS /ws/scene ───────────▶│                                     │
  │───── hello{sessionId,userId} ──────▶│ SceneSessionRegistry.bind           │
  │─────────── scene_state ────────────▶│ 更新场景快照                        │
  │                                     │◀──── tools/call + X-Session-Id ─────│
  │                                     │ SceneDispatcher.dispatch            │
  │◀────── action 帧 + actionId ────────│                                     │
  │──────── action_result{ok} ─────────▶│                                     │
  │                                     │──── 工具结果（成功/失败原因） ─────▶│
```

关键点：

- 路由键是 `X-Session-Id`，由 agent 从聊天入口的 `sessionId` 透传，**不能由 LLM 填**。
- 缺省时 `singleSessionFallback=true` 只在恰好一条连接时兜底，多条连接直接拒绝。
- `SceneDispatcher` 同步等待 `action_result`，默认超时 `scene.action-timeout-ms=15000`；agent 侧场景客户端超时 25s，必须大于它。
- 同一 `sessionId` 新连接顶掉旧连接；`scene.redispatch-on-reconnect=true` 时在途动作重发给新连接（动作需幂等）。
- 破坏性动作（`scene_set_area_state`、`scene_set_inspection_state`）由 `scene.destructive-enabled=false` 挡住。
- 页面未连接时立即失败，不挂起。

### 2.4 D：场景状态同步与重连

```text
  UE 页面                     sidecar
  │──── WS /ws/scene + hello ────▶│ bind；同 sessionId 关闭旧连接
  │──────── scene_state ─────────▶│ 写入 SceneSession 快照
  │ ※ 页面刷新/断网              │
  │── 重连 + hello(sessionId) ───▶│ 新连接替换旧连接
  │◀──── 重发在途 action 帧 ──────│
  │ ※ 断连后会话保留 30 分钟再回收
```

### 2.5 知识库检索链路

agent 有两条路径，按配置选择：

1. `KB_BASE_URL` + `KB_API_KEY` 都配置 → `mcp_client/knowledge_http_client.py` 直连平台检索接口；
2. 两者留空 → 回落 sidecar `/mcp/knowledge`（sidecar 再调 RAGFlow）。

## 3. agentic-app 内部架构

### 3.1 入口与路由

`app.py` 是 FastAPI 入口：

| 入口 | 作用 |
|---|---|
| `WS /chat/{user_id}/{session_id}` | 主对话；所有普通消息都从这里进 |
| `WS /gen_doc/...` | 统计报告分章节生成 |
| `WS /asr/...` | 语音识别 + LLM 纠错 |
| `POST /upload/image` | 图片上传，返回 URL 供多模态对话引用 |

主对话的分流顺序：

1. `payload.mode == "kb"` → 知识库直连；
2. `payload.mode == "scene"`、上一轮场景指令在等参数、或自动识别命中场景意图 → 场景控制图；
3. 其余按启动级开关走 **Loop 新链路** 或 **旧 LangGraph 链路**。

启动级开关 `AGENT_MODE`：

| 值 | 行为 |
|---|---|
| `loop` | 全量走 Loop 新链路（单请求 `mode=legacy` 仍可回滚） |
| `legacy` | 全量走旧逻辑（单请求 `mode=loop` 仍可试用） |
| `auto`（默认） | 按 `LOOP_ROLLOUT_PERCENT` / `LOOP_ROLLOUT_USERS` 灰度 |

### 3.2 Loop 链路

```text
WS /chat
  └─ agent.loop.ws_bridge.handle_chat
       ├─ ToolRegistry：13 个业务域（person/security/canteen/vehicle/information/
       │   energy/meeting/fire/perimeter/device/devicequery/overview/inspection）
       ├─ Executor：参数校验 + before/after 钩子 + 超时
       └─ LoopAgent：调模型 → 执行 tool_calls → 回填 → 再调模型
```

要点：

- **工具声明式**：每个域一个 `DomainSpec`，工具是 `ToolSpec`（名称、描述、JSON Schema、execute），新增域只加声明，不写图。
- **工具串行执行**：与现有 MCP 客户端/连接模型一致，且多数工具存在先后依赖。
- **不隐式重试**：工具失败以 `is_error` 回给模型，由模型决定换参数还是转述。
- **超时即结束**：`MCP_CALL_TIMEOUT` 控制单次 MCP 调用，`LOOP_TOOL_TIMEOUT` 是外层兜底且必须略大；
  超时后不再重连重试，`ToolTimeoutError` 直接回到 agent，本轮由 `_finalize` 收尾，避免用户无限等待。
- **连续失败保护**：同一轮连续 `max_tool_errors=2` 次失败即停止重试并返回明确提示。
- **动态发现**：`LOOP_DISCOVER=1` 时启动后动态发现 `devicequery` 等端点的额外工具；失败只告警，不影响显式工具。

### 3.3 意图识别与追问

- **顶层意图**：`BAAI/bge-small-zh-v1.5` 本地 embedding，中心向量余弦相似度，阈值 0.65；低于阈值归 `other`。
- **槽位抽取**：`jionlp` 时间解析 + 正则 + 区域/餐次/人名词典；不调模型。
- **追问 Handler**：按域判断缺参、生成追问、识别用户回复是否相关；连续 3 次不相关放弃。
- **新意图接管**：追问态下识别出其他域意图且过阈值时，放弃当前任务，改走新意图流程。

### 3.4 旧版 LangGraph 链路（灰度保留）

- 13 个业务域图结构对称：`check_missing_params → ask_param / check_date → call_tool → finalize`。
- 通用兜底 `graph/reactive_pipeline.py`：意图 → 追问 → Agent → 评估 → 合成。
- 报告生成 `graph/gen_doc_pipeline.py`、语音纠错 `graph/asr_pipeline.py` 仍在用。
- Loop 全量稳定后可删除旧图；在此之前两者共享 `agent/intent` 与 `memory`。

### 3.5 MCP 客户端层

| 模块 | 作用 |
|---|---|
| `mcp_client/mcp_config.py` | 读 YAML、补全 `mcp_base_url`、注入 `MCP_API_KEY` 到每个 server 的 `Authorization` |
| `mcp_client/mcp_loader.py` | `MultiServerMCPClient` 并发加载（旧链路 / 工具清单） |
| `agent/loop/runtime.py` | 官方 MCP SDK `streamablehttp_client`，每 server 一个长连接，超时不重试 |
| `mcp_client/knowledge_mcp_client.py` | `/mcp/knowledge` 直连客户端（`direct_client: true`） |
| `mcp_client/scene_mcp_client.py` | `/mcp/scene` 直连客户端，逐请求注入 `X-Session-Id` |
| `mcp_client/knowledge_http_client.py` | 平台知识库 HTTP 直连（优先于 `/mcp/knowledge`） |

Agent 的 `mcp_server_config.yaml` 当前启用 **15 个端点**：13 个 Platform 业务端点 +
`knowledge` + `scene`。sidecar 侧共有 17 个端点（多出 `pathFind`、`utils`，agent 暂未接）。

### 3.6 记忆、模型、文档、语音

- **会话状态**：追问态 `IntentState` 按 `user:session` 存内存，默认 5 分钟过期；Loop 会话单独管理。
- **对话历史**：JSON / SQLite / MySQL 可配置持久化；服务重启后可恢复。
- **模型**：`models/llm.py` 统一工厂，OpenAI 兼容（DeepSeek / GLM / vLLM）或 Ollama；
  `LLM_API_KEY` 优先，回退 `OPENAI_API_KEY`。
- **报告生成**：`doc_tools/` 模板 + `graph/gen_doc_pipeline.py`，流式回传进度。
- **语音**：Whisper 流式识别 + LLM 文本纠错，初始化失败降级为不可用。

## 4. mcp-sidecar 内部架构

### 4.1 过滤器与拦截器

| 组件 | 作用 |
|---|---|
| `EndpointPortGuardFilter` | 按本地端口隔离路径；未知端口默认拒绝 |
| `McpApiKeyFilter` | `/mcp/**` 校验 `Authorization: Bearer` 或 `X-MCP-API-Key`，未配置 key 时全 401 |
| `McpRequestSizeLimitFilter` | `/mcp/**` 请求体上限 1 MiB，覆盖 Content-Length 与 chunked |
| `OriginHandshakeInterceptor` | WebSocket Origin 白名单；非浏览器客户端无 Origin 时交给 token 鉴权 |
| `AuthHandshakeInterceptor` | 从 `Authorization` 或 query `token` 提取 token/userId/sessionId |

### 4.2 2222：聊天代理与场景

- `ProxyWebSocketHandler`：校验 token+userId → 限流 → 代理到 `agent:8001/chat`、`/gen_doc`。
- `SceneWebSocketHandler`：`hello` 校验并绑定 userId，接收 `scene_state`、`action_result`，下发 `action` 帧。
- `SceneSessionRegistry`：同 sessionId 新连接顶掉旧连接；断连保留 30 分钟；全局会话上限。
- `LLMChatLimiter`：进程内并发许可，断开时按用户计数释放。

### 4.3 2223：MCP 服务端

- 每个端点一个 `WebMvcStreamableServerTransportProvider` + `McpSyncServer`，
  通过 `SyncMcpAnnotationProviders.toolSpecifications(List.of(bean))` 静态注册该端点的全部 `@McpTool`。
- 所有工具对客户端可见，没有按请求裁剪/隐藏工具的逻辑。
- 17 个端点、113 个工具，详见第 5 节。

### 4.4 Platform / RAGFlow 客户端

- `PlatformApiCallServiceImpl`：服务账号登录（RSA 或显式允许的明文）、token 缓存、
  业务接口 GET/POST、鉴权失效自动重试。
- `RagflowApiClient`：知识库检索，供 `/mcp/knowledge` 使用。
- 平台 token 只存内存，不落盘。

## 5. MCP 端点清单

sidecar 当前共 **17 个 MCP Streamable HTTP 端点、113 个工具**：

## 6. 配置与运行形态

### 6.1 sidecar Profile

| 配置项 | `local` | `server` |
|---|---|---|
| `server.port` | 2222 | 2222 |
| `mcp.internal-port` | 2223 | 2223 |
| `mcp.internal-address` | `127.0.0.1` | `${MCP_INTERNAL_ADDRESS:0.0.0.0}`（compose） |
| `mcp.api-key` | `${MCP_API_KEY}` | `${MCP_API_KEY}` |
| Platform baseUrl | `http://localhost:9500/platform` | `http://10.0.0.5:9500/platform` |
| agent WS 地址 | `ws://127.0.0.1:8001/chat/...` | `ws://agentic-app:8001/chat/...` |

### 6.2 关键环境变量

| 变量 | 默认值 | 作用 |
|---|---|---|
| `MCP_PORT` | `2222` | sidecar 宿主机回环端口（Nginx 反代目标） |
| `MCP_INTERNAL_PORT` | `2223` | MCP 内网端口（仅 expose） |
| `MCP_INTERNAL_ADDRESS` | `0.0.0.0`（compose） | 2223 监听地址；本地默认 `127.0.0.1` |
| `MCP_API_KEY` | 无（必须配置） | `/mcp/**` 应用层鉴权；sidecar 与 agent 必须一致 |
| `APP_PORT` | `8001` | agent 端口（仅容器网络） |
| `SPRING_PROFILES_ACTIVE` | `server` | sidecar profile |
| `SCENE_MCP_URL` | `http://mcp-sidecar:2223/mcp/scene` | agent 场景端点 |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 无 | agent 大模型配置 |
| `AGENT_MODE` | `auto` | `loop` / `legacy` / `auto` |
| `MCP_CALL_TIMEOUT` | 代码默认 | 单次 MCP 调用超时（秒） |
| `MCP_CONNECT_TIMEOUT` | 代码默认 | MCP 建连超时（秒） |
| `LOOP_TOOL_TIMEOUT` | 代码默认 | 外层工具超时，必须大于 `MCP_CALL_TIMEOUT` |
| `LOOP_ROLLOUT_PERCENT` / `LOOP_ROLLOUT_USERS` | 空 | `AGENT_MODE=auto` 的灰度比例/白名单 |

### 6.3 部署形态

- agent 与 sidecar 在同一 compose 网络，agent 通过 `mcp-sidecar:2223` 访问 MCP；
- 2222 只绑宿主机回环，供同机 Nginx 反代；
- 不发布 2223、8001、9970；
- 没有 Nginx 的纯内网联调可临时 `-p 2222:2222`，生产不要这样做。

## 7. 安全边界与已知限制

1. **MCP 两层防线**：端口隔离（2223 不发布、2222 访问 `/mcp/**` 返回 404）+ `MCP_API_KEY`。
2. **`/llm/**`、`/ws/**` 有应用层鉴权**：平台 token + userId，失败返回 `UNAUTHORIZED`。
3. **`/ws/scene` 会话绑定**：hello 时校验 token/userId，sessionId 绑定 userId，禁止跨用户顶替；全局会话有上限。
4. **MCP API Key 是共享服务密钥**：不是用户身份，无过期和用户绑定；所有 agent 实例共用一个值。
5. **场景动作白名单**：只有 `SceneActions.ALL` 中的动作可下发；破坏性动作默认关闭。
6. **单会话兜底只适合联调**：多用户部署必须由 agent 逐请求注入 `X-Session-Id`。
7. **请求体上限**：`/mcp/**` 1 MiB，超限 413。
8. **传输加密（SEC-17）**：当前为内网部署——agent/sidecar 同 Docker 网络，2222 不对外发布，
   TLS 不在应用层启用；Nginx → 2222、sidecar → Platform 两段为内网明文，按网络边界接受风险。
   出现“2222 直接暴露到办公网/公网、跨不可信主机部署、接入公网第三方调用方”时，
   必须恢复入口 TLS 并重新评估。
9. **凭据**：平台账号、RAGFlow/Redis/DB 凭据只放未跟踪的 `.env`；已进入 Git 历史的旧凭据仍需轮换（SEC-02/03）。
10. **Redis 未接入业务**：compose 中的 redis 是预留服务，健康检查已关闭避免日志膨胀。
